# Spec Delta

## Purpose

统一数据库与应用层的北京时区口径，让新增时间字段和“当日”类业务判断不再依赖 MySQL 或操作系统默认时区，并明确历史数据不回填的边界。

## ADDED Requirements

### Requirement: 数据库时间按北京时间写入

系统 SHALL 让每个 MySQL 连接会话使用配置的时区（默认 `+08:00`），使 `CURRENT_TIMESTAMP`、`NOW()` 与 `ON UPDATE CURRENT_TIMESTAMP` 产生的 `created_at`、`updated_at`、`finished_at` 等字段表示北京时间。该规则 MUST 同时作用于连接池与初始化建表连接，MUST NOT 修改既有表结构或列类型。

#### Scenario: 新记录时间为北京时间

- **WHEN** 用户在任意时刻创建闯关、出题任务、答题记录或知识库文档
- **THEN** 对应记录的 `created_at` 与北京时间一致，历史列表与详情展示不再偏差 8 小时

#### Scenario: 更新时间按北京时间

- **WHEN** 用户修改昵称、头像或任务状态更新
- **THEN** `updated_at`、`finished_at` 等字段写入北京时间

#### Scenario: 连接池所有连接生效

- **WHEN** 应用通过连接池获取任意一条连接执行写操作
- **THEN** 该连接的会话时区均为配置的北京时间，而不是 MySQL 服务器的 UTC 默认值

#### Scenario: 时区可配置

- **WHEN** 部署环境需要其他时区
- **THEN** 可通过 `MYSQL_TIME_ZONE` 环境变量覆盖默认 `+08:00`，未配置时使用北京时间

### Requirement: 自然日按北京时间计算

系统 SHALL 按北京时间自然日计算“当日”类业务，包括每日配图用量的日期键与重置时点；MUST NOT 直接依赖服务器操作系统的 `date.today()` 或 UTC 日期。

#### Scenario: 北京时间零点重置

- **WHEN** 北京时间进入新的一天
- **THEN** 每日配图用量按新日期重新计算，前一日用量不影响新额度

#### Scenario: 服务器时区非北京时间

- **WHEN** 应用运行在 UTC 或其他时区的服务器上
- **THEN** 系统仍按北京时间判断“今日”，配图用量日期与北京时间一致

### Requirement: 历史数据不回填

本次变更 MUST NOT 修改已存在的历史时间字段。已有记录保持部署前存储的 UTC 值，接口按数据库原值返回；用户查看旧记录时仍可能看到比北京时间慢 8 小时的时间，系统 MUST NOT 对旧值做自动加减或猜测性修正。

#### Scenario: 旧记录保持原值

- **WHEN** 变更上线后用户查看变更前创建的闯关历史
- **THEN** 该记录的 `created_at` 与数据库原值一致，不因时区修正而被批量改写

#### Scenario: 旧记录与新记录共存

- **WHEN** 同一列表同时包含变更前与变更后创建的记录
- **THEN** 系统分别按各自存储值展示，新记录为北京时间，旧记录保持原有偏移，不报错也不阻断页面

#### Scenario: 上线时仍有进行中任务

- **WHEN** 部署瞬间存在变更前创建且仍在运行的异步任务
- **THEN** 服务启动时的既有清理逻辑将其置为失败，避免旧 UTC 时间参与新的超时判断
